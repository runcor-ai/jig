A Jig script calling a Jig script

Levels stack. A Jig script can itself become a step. Declared as a command, with its inputs as variables and its result as an answer checked against a schema like any other, a whole way of working is called as one line from the level above. The game script, about forty lines with its build, tests, verification, fix rounds and review, becomes make_game. Like any single step, it declares the shape of its answer, so r.output.id and r.output.tests below are checked against that schema when the game script returns, before the factory reads them. This is the whole factory that builds three games at the same time, without its comments:

GAMES = [{"id": "PONG-003", "file": "pong.md"},
         {"id": "TETRIS-002", "file": "tetris.md"},
         {"id": "SNAKE-002", "file": "snake.md"}]

results = make_game(each=GAMES, parallel=3)

passed = []
for r in results:
    if r.status == "completed":
        passed.append(r.output.id)
    elif r.output and "tests" in r.output:
        print(f"{r.output.id} needs a look: tests {r.output.tests}, verify {r.output.verdict}")
    else:
        print("a game stopped early; see its record in .jig/")

print(f"{len(passed)} of {len(GAMES)} games pass: {passed}")
if len(passed) != len(GAMES):
    fail(f"{len(GAMES) - len(passed)} game(s) did not pass")

Run on 14 November 2026, the three games were built at the same time in five minutes, and each passed its tests and had every must-have requirement verified, with no fix rounds. The inner steps are still checked and recorded on their own artifacts, so one can always go down a level and look, which is what section 02 asks of a level. A way of working rated at one level can then be used as a component at the next, as a rated bolt is in a machine. The syntax is in the language reference (calling another script) and the command format in script commands; the factory and the game script are factory/factory.jig and factory/game.jig.
